# Choosing Direct or Vagrant

TurboPanel runs its whole development stack on Debian. You get that Debian in one of two ways, and the setup script, which is not merged yet (see [Contribute Without Access](/docs/development/contribute-without-access)), asks once and stores the answer in `.turbopanel-dev-mode` in the folder that holds the repos.

## The Choice

| Your machine | Use |
| --- | --- |
| macOS | **Vagrant** only (UTM provider, Debian 12 guest today) |
| Linux, Debian 13, already a virtual machine | **Direct** (recommended; nested virtual machines are slow) |
| Linux, Debian 13, bare metal | Either |
| Other Linux | **Vagrant** (libvirt provider) |
| Windows | Not supported |

**Direct** needs Debian 13 (Trixie) as a full virtual machine or bare metal, never an LXC container, with 4 or more CPUs, 8 GB or more of RAM and 40 GB of disk, and a non-root user with passwordless sudo. The setup follows the [Direct VM guide](https://github.com/TurboPanel/dev/blob/trunk/docs/dev-environment.md). **Vagrant** needs Vagrant and a provider on your computer; see [Prerequisites](/docs/development/prerequisites).

## Where Things Happen

| | Vagrant | Direct |
| --- | --- | --- |
| Where you edit | On your computer; the repos are mounted into the guest | On the Debian machine itself, for example over a remote editor |
| Where you commit | **On your computer (the host)** | On the Debian machine |
| Hooks on commit | Secret scan only; CI checks the rest | The hooks in the toolchain on the machine |
| Where you run the stack | `vagrant ssh`, then `dev/console` | `dev/console` |
| Where tests run | Inside the guest, or in CI | On the machine, or in CI |

In Vagrant mode the host has no Node or Deno tree, so the host commit hooks only run the secret scan, which is never skipped. Formatting, typechecks and tests are caught by CI, so format your changed files yourself before you commit (see [Contribute Without Access](/docs/development/contribute-without-access#make-a-change-and-open-a-pull-request)).

Full suites are heavy. On a 16 GB computer the 8 GB guest is tight, and CI is the usual place to run everything.
