# Refresh a stuck daemon

Sometimes a managed server **looks offline in the UI** even though the daemon is still running, or the **Update button fails** because the node is on an old build. Use the **`turbopanel-update` helper** that `run.sh` installs into the managed FHS tree at `/opt/turbopanel/bin/turbopanel-update` — it is **not** a CDN short URL like `run.sh`, and it needs **no source checkout**.

## When to use this

Use the update helper when:

- The server badge shows **Offline** but the daemon service is running (`systemctl status turbopaneld`)
- The **Update** button in the UI errors or does nothing (common on very old builds)
- You changed **update channel** in `/etc/turbopanel/daemon.env` and want to pull from the new channel immediately
- You want to **reconcile** after a bad upgrade (daemon disabled, wrong version, etc.)

<Callout type="info" title="Co-located dev hosts">
  This page covers **managed servers** (FHS tree). If your control-plane host was
  provisioned with the [turbopanel-dev](https://github.com/turbopanel/turbopanel-dev)
  console, update it from the console (**Sync Dev Build** / **Upgrade System**)
  instead — that host runs the daemon from a source checkout, not `/opt/turbopanel/bin`.
</Callout>

<Callout type="info" title="UI vs cell panel">
  The server list reads a **Postgres projection** for online/offline. The **Cell** panel reads live WebSocket state. If those disagree, the daemon is usually fine — run an update to refresh both the installed binary and presence.
</Callout>

## One-command update (recommended)

On the managed server, as **root**:

```bash
sudo sh /opt/turbopanel/bin/turbopanel-update
```

That helper:

1. Reads your **license** from `/var/lib/turbopanel/license.id` + `license.token` (saved at install)
2. Reads your **update channel** from `/etc/turbopanel/daemon.env` (`TURBOPANEL_UPDATE_CHANNEL`, default `trunk`)
3. Reads your **control plane URL** and **CA** from `daemon.env` when self-hosted (`TURBOPANEL_INSTANCE_URL`, `TURBOPANEL_INSTANCE_CA`, else `/etc/turbopanel/instance-ca.pem`)
4. Downloads the latest **`run.sh`** from `https://trbp.nl/run.sh` (the CDN installer)
5. Reinstalls the daemon binary + orchestration tree, re-runs Ansible, and restarts `turbopaneld.service`

<Callout type="warning" title="Not a curl pipe">
  Unlike first-time install, there is no `trbp.nl/update.sh`. Always run the installed helper at the path above. Piping `curl | sh` as a non-root user will hang or fail.
</Callout>

### Self-hosted control plane

Pass `--host` only if you need to override `daemon.env`:

```bash
sudo sh /opt/turbopanel/bin/turbopanel-update \
  --host https://<instance-host>:8443
```

## Change update channel

```bash
sudo sh /opt/turbopanel/bin/turbopanel-update --channel trunk
```

Preview without changing anything:

```bash
sudo sh /opt/turbopanel/bin/turbopanel-update --channel trunk --dry-run
```

## If the license file is missing

The update helper reads:

| File | Purpose |
| ---- | ------- |
| `/var/lib/turbopanel/license.id` | Organization license UUID |
| `/var/lib/turbopanel/license.token` | Secret token (shown **once** at license creation) |

Check on the server:

```bash
sudo ls -la /var/lib/turbopanel/
```

If those files are missing, create a **new license** in the TurboPanel UI (**Servers → Licenses**), copy the install command immediately, and pass `--license` manually:

```bash
sudo sh /opt/turbopanel/bin/turbopanel-update \
  --license <base64url-from-install-command>
```

## Manual fallback (same as the helper)

If you prefer not to use `turbopanel-update`, build the license argument yourself and pipe **`run.sh`** only:

```bash
LICENSE_B64=$(python3 -c "
import base64
id = open('/var/lib/turbopanel/license.id').read().strip()
tok = open('/var/lib/turbopanel/license.token').read().strip()
print(base64.urlsafe_b64encode(f'{id}:{tok}'.encode()).decode().rstrip('='))
")

curl -fsSL https://trbp.nl/run.sh | sudo sh -s -- \
  --license "$LICENSE_B64" \
  --channel trunk
```

Always use **`curl … trbp.nl/run.sh`** for the installer — not a local copy from the tree you are trying to replace.

## Verify after update

```bash
sudo systemctl status turbopaneld
curl -sS https://turbopanel.app/api/daemon/v1/version   # or your instance URL
```

In the UI, refresh the servers page — the node should show **Online** with a current commit on the update row.
