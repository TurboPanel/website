# Installation

TurboPanel is split across multiple repositories. Installation paths depend on whether you are setting up **contributor local dev**, a **self-hosted control plane**, or an **additional agent node**.

## Contributor local development

Bootstrap all sibling repos and start Tilt from [turbopanel-dev](https://github.com/turbopanel/turbopanel-dev):

```bash
curl -fsSL https://develop.trbp.nl | sh
cd dev   # or your turbopanel-dev checkout path
tilt up
```

See [Local development](/docs/getting-started/development) for URLs, ports, and day-to-day workflow.

## Self-hosted control plane (Debian / Ubuntu VM)

<Callout type="info" title="No public install script yet">
  Self-hosted production today uses **`develop.sh`** on a VM with sibling `instance/` and `daemon/`
  checkouts. A one-line public installer (like the old `turbopanel.sh` flow) is not available yet.
</Callout>

On a fresh Debian or Ubuntu host:

```bash
cd instance
./develop.sh
```

`develop.sh` bootstraps the daemon orchestration runtime, enables co-located dev mode (`TURBOPANEL_DEV_INSTANCE=1`), installs `turbopanel-daemon.service`, and tails journals. The daemon then runs Ansible to install instance (Deno), Caddy, UI, and Postgres.

- **HTTPS entrypoint:** `https://<host>:8443` (Caddy)
- **Install wizard:** first visit prompts host PAM + superadmin setup (Deno path)
- Trust the platform CA from `GET /api/daemon/v1/instance/ca` or `instance/certs/ca.crt`

Details: [Control plane](/docs/deployment/control-plane).

## Cloud-hosted (Workers)

The instance can run on Cloudflare Workers (`pnpm deploy:workers` in the instance repo). Managed edge features such as **Durable Objects** for daemon coordination are **not implemented yet** — remote daemons today connect over HTTPS/WSS to a reachable instance URL. See [Control plane](/docs/deployment/control-plane).

## Additional agent nodes

Install the daemon on servers that should be managed remotely (not the co-located control plane):

```bash
curl -fsSL https://raw.githubusercontent.com/turbopanel/turbopanel-cdn/trunk/install.sh \
  | sudo bash -s -- \
      --instance-url https://<instance-host>:8443
```

Replace host and port with where the instance is reachable from the node. The installer fetches the platform CA from `/api/daemon/v1/instance/ca` automatically for HTTPS instances.

Full options and examples: [Daemon setup](/docs/deployment/daemon-setup).

## Prerequisites (all paths)

- Linux server (Debian/Ubuntu recommended for Ansible paths)
- Docker (daemon running)
- For Tilt dev: Node.js ≥ 24, pnpm ≥ 11, Tilt — see [Prerequisites](/docs/development/prerequisites)
