# Installation

TurboPanel is split across multiple repositories. Installation paths depend on whether you are setting up **contributor local dev**, a **self-hosted control plane**, or an **additional managed server daemon**.

## Contributor local development

Bootstrap the dev console from [turbopanel-dev](https://github.com/turbopanel/turbopanel-dev):

```bash
curl -fsSL https://develop.trbp.nl | sh
cd turbopanel-dev
./console
```

The one-liner clones or updates `./turbopanel-dev` in your current directory. `./console` installs the pinned Deno runtime (sudo on first run), caches dependencies, and launches the Ink dev console. From the console, use **Start dev stack** to install the daemon, bootstrap orchestration, and bring up instance + Caddy + UI via systemd.

See [Local development](/docs/getting-started/development) for console areas, URLs, and day-to-day workflow.

## Self-hosted control plane (Debian / Ubuntu VM)

<Callout type="info" title="No public install script yet">
  Self-hosted production uses the same [turbopanel-dev](https://github.com/turbopanel/turbopanel-dev)
  console on a VM. A one-line public installer (like the managed-node CDN flow) is not available yet
  for control planes.
</Callout>

On a fresh Debian or Ubuntu host:

```bash
curl -fsSL https://develop.trbp.nl | sh
cd turbopanel-dev
./console
```

In the console, choose **Start dev stack**. This writes developer identity into the daemon `.env`, bootstraps the daemon orchestration runtime, enables co-located dev mode (`TURBOPANEL_DEV_INSTANCE=1`), installs `turbopanel-daemon.service`, and tails journals. The daemon then runs Ansible to install instance (Deno), Caddy, UI, and Postgres under `/opt/turbopanel/platform/`.

- **HTTPS entrypoint:** `https://<host>:8443` (Caddy)
- **Install wizard:** first visit prompts host PAM + superadmin setup (Deno path)
- Trust the platform CA from `GET /api/daemon/v1/instance/ca` or `instance/certs/ca.crt`

Details: [Control plane](/docs/deployment/control-plane).

## Cloud-hosted (Workers)

The instance can run on Cloudflare Workers (`pnpm deploy` in the instance repo; requires `TURBOPANEL_DATABASE_URL` for migrations and `CLOUDFLARE_ENV`, e.g. `live` or `testing`, matching `wrangler.jsonc`). Managed edge features such as **Durable Objects** for daemon coordination are **not implemented yet** — remote daemons today connect over HTTPS/WSS to a reachable instance URL. See [Control plane](/docs/deployment/control-plane).

## Additional managed server daemons

Install the daemon on servers that should be managed remotely (not the co-located control plane):

```bash
curl -fsSL https://raw.githubusercontent.com/turbopanel/turbopanel-cdn/trunk/install.sh \
  | sudo bash -s -- \
      --instance-url https://<instance-host>:8443
```

Replace host and port with where the instance is reachable from the node. The installer fetches the platform CA from `/api/daemon/v1/instance/ca` automatically for HTTPS instances.

Full options and examples: [Daemon setup](/docs/deployment/daemon-setup).

## Prerequisites (all paths)

- Linux server (Debian/Ubuntu recommended for Ansible paths)
- Docker (daemon running)
- SSH access to GitHub for platform repo clones (`git@github.com:turbopanel/...`)
- For local dev: see [Prerequisites](/docs/development/prerequisites)
