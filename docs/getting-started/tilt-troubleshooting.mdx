# Dev console troubleshooting

Use this page when `./console` fails to start the stack, systemd units are unhealthy, or Deno vs Workers instance mode behaves unexpectedly. For database schema issues, see [Database troubleshooting](/docs/getting-started/database-troubleshooting).

## Console will not start

- Verify Deno runtime: `/opt/turbopanel/runtimes/deno/current/deno --version`
- First run may require **sudo** to create `/opt/turbopanel/runtimes` — re-run `./console` after granting privileges.
- Update the checkout: `sh scripts/develop.sh` from inside `turbopanel-dev`.

## Dev stack will not start

- Open the **Status** area in `./console` and check unit states.
- Follow logs from the **Actions** area (**Follow logs**).
- Verify Docker is running: `docker version` (Postgres runs in Docker).
- Confirm the daemon checkout exists: `/opt/turbopanel/platform/daemon/`.
- If the daemon repo is missing, use **Install daemon** in the Actions area first, then **Start dev stack**.

## Instance runtime not switching

- Use the **Instance** area in `./console` (**Switch to Deno Mode** / **Switch to Workers Mode**).
- Workers mode requires `pnpm dev` running manually in `/opt/turbopanel/platform/instance/`.
- Deno mode requires `/run/turbopanel` to exist and `turbopanel-instance.service` to be active.

## Port conflicts

- Symptom: `address already in use` in journal logs.
- Fix: stop the conflicting process or change `CADDY_PORT` in the daemon `.env` and restart Caddy.
- **Example (Unix):** `lsof -ti :8443 | xargs kill` (replace with the port from the error).

## Caddy 502 on https://localhost:8443

- Ensure `turbopanel-instance.service` and `turbopanel-ui.service` are active before Caddy serves traffic.
- Deno mode: confirm `/run/turbopanel/instance.sock` exists and is group-writable.
- Workers mode: wrangler must bind `0.0.0.0` (see `wrangler.jsonc` `dev.ip`) if Caddy reaches it over TCP.

## TLS / certificate warnings

- Trust `instance/certs/ca.crt` (under the platform checkout) in your OS or browser.
- Re-run the `instance-certs` Ansible role or `pnpm cert:generate` in the instance checkout if certs are missing.

## Schema sync failures

- Run `./sync.sh --force` from the instance checkout.
- Ensure Postgres is healthy (`docker ps` / **Services** section in the developer console).
- See [Database troubleshooting](/docs/getting-started/database-troubleshooting).

## Expo / UI not loading

- Confirm `turbopanel-ui.service` is active.
- Caddy proxies non-API traffic to Expo when `TURBOPANEL_UI_MODE=dev`.

## Platform checkouts missing

The console installs only the **daemon** repo. Instance, UI, and website are installed by the daemon via Ansible when **Start dev stack** runs. If checkouts are incomplete, restart the daemon unit and check `journalctl -u turbopanel-daemon -f` for Ansible errors.
