# Tilt troubleshooting

Use this page when the Tilt UI shows errors, ports clash, or Workers vs Deno instance mode behaves unexpectedly. For database schema issues, see [Database troubleshooting](/docs/getting-started/database-troubleshooting).

## Instance runtime not switching

- Use the Tilt UI **Switch to Deno Mode** / **Switch to Workers Mode** nav buttons (updates `dev/.env`, re-syncs env, recreates Caddy, restarts instance).
- **Manual:** set `TURBOPANEL_INSTANCE_RUNTIME=workers` or `deno` in `dev/.env`, then `tilt down && tilt up`.
- Deno mode requires Deno on the host.

## Services will not start

- Open the failing resource in the Tilt UI and read the log tail.
- Verify toolchain: `node --version`, `pnpm --version`, `tilt version`, `docker version`.
- Confirm sibling repos exist: `instance/`, `ui/`, `website/` next to `dev/` — run `sh pull.sh` if missing.
- **Ports:** Caddy **8443**, website **19820**, wrangler **18787**, Expo **8081**, Postgres **5432**, Tilt **10350**, Mailpit **19825–19826**.
- **Clean restart:** `tilt down && tilt up`.

## Port conflicts

- Symptom: `address already in use` in logs.
- Fix: `tilt down`, or stop the process holding the port.
- **Example (Unix):** `lsof -ti :8443 | xargs kill` (replace with the port from the error).

## Caddy 502 on https://localhost:8443

- Ensure the `instance` and `ui` resources are healthy before `caddy` starts (Tilt dependency order).
- Workers mode: wrangler must bind `0.0.0.0` (see `wrangler.jsonc` `dev.ip`) so Docker Caddy can reach it via `host.docker.internal`.
- Deno mode: confirm `/run/turbopanel` exists and the instance bound `instance.sock`.

## TLS / certificate warnings

- Trust `instance/certs/ca.crt` in your OS or browser.
- Re-run `instance-certs` in Tilt (or `pnpm cert:generate` in `instance/`) if certs are missing.

## instance-db / schema sync failures

- Check `instance-db` logs — it runs `./sync.sh --force` from `instance/`.
- Ensure Postgres is healthy and `instance/.env` has connection vars (synced from `dev/.env`).
- See [Database troubleshooting](/docs/getting-started/database-troubleshooting).

## Expo / UI not loading

- Confirm `ui` resource is running on `EXPO_PORT` (default **8081**).
- Caddy proxies non-API traffic to Expo when `TURBOPANEL_UI_MODE=dev`.

## Wrangler not found (Workers mode)

- Run `pnpm install` in `instance/` (Tilt `instance-deps` should do this on first start).
