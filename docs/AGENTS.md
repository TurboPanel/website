## Site & Docs Conventions

- **Database reference (`docs/database/`) is generated; never edit it by hand.** One overview page plus one page per data dictionary group, with a `meta.json`. The control plane prints the content (`node scripts/schema-docs.mjs --json` in `turbopanel`, which reads `src/db/schema-descriptions.ts` and the newest migration snapshot); this repo turns it into pages with `scripts/sync-schema-docs.mjs`. Regenerate: `(cd ../turbopanel && node scripts/schema-docs.mjs --json) > /tmp/schema.json && pnpm schema:sync /tmp/schema.json`; `pnpm schema:sync --check /tmp/schema.json` reports drift without writing. The pages are committed so the docs build never needs the control plane repo. Rerun it whenever a control plane change touches the schema descriptions or adds a migration, and commit the result.
- **MDX inline components:** keep `<File>` (and other inline JSX) on the *same line* as the surrounding prose. A JSX tag starting its own line is parsed as a block, which splits the paragraph and strands punctuation on its own row.
