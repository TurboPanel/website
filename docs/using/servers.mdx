# Servers

A **server** is a Linux host running the TurboPanel daemon, enrolled into one organization. Everything you deploy runs on one. This chapter is the app side of your servers: **Servers** (`/<org>/servers`), a server's **control panel**, pending registration **Keys**, and the organization-wide **Settings**. Installing the daemon by hand, updating it from the shell, and what lives where on the host are the operator's pages: [Daemon setup](/docs/deployment/daemon-setup) and [Daemon update](/docs/deployment/daemon-update).

## The model

| Term | Meaning |
| --- | --- |
| **Registration key** | A one-shot credential the app mints when you add a server. It is embedded in the install command; the daemon consumes it at enrollment and it is bound to that server from then on. An unconsumed key is a **pending key**. |
| **Daemon** | `turbopaneld` on the host: enrolls with the key, holds a signed key pair, streams facts and metrics, and executes the commands the control plane queues (deploys, reboots, updates). It connects **out** to the control plane; nothing connects in. |
| **Co-located server** | On self-hosted, the control plane's own host is also a server — enrolled at install and badged **Platform Server**. It cannot be deleted, its key cannot be revoked, and it updates with the control plane rather than through the app. |
| **Capacity** | An owner-set ceiling on how many servers the organization may hold (**Servers → Settings → Server capacity**); enrolled servers and pending keys both count. On High Availability the purchased [licenses](/docs/using/billing) bound it as well. |
| **Machine class** | Physical or virtual. Decides whether the sensor family is expected; inferred from discovered sensors unless pinned. |

Two rules:

- **TurboPanel observes host interfaces; it does not configure them.** Addresses and routes are the host's. The app reads what the daemon reports and pins meaning onto it (datacenter network membership, addresses for hosting). **The host firewall is TurboPanel's.** The installer removes `ufw`, `firewalld` and `iptables-persistent` from every host it installs on (they do not compose with Docker, and a host that shipped with `ufw` active kept the control plane's **8443** closed), so nothing on the host blocks the control plane or a published service port after install. The rules TurboPanel applies in their place — derived from what the control plane deploys, with organization defaults and per-server rules on top — are shown as a **preview** on each server's **Firewall** tab today and are not applied yet; until enforcement is switched on, restrict access from outside the host (cloud security groups, a provider firewall) if you need to. See [Firewall](/docs/using/firewall).
- **A rebuilt host is a new server.** A key is consumed once; a host that is reinstalled from scratch enrolls with a fresh key and appears as a new server row.

## Before you begin

- A Debian 13 (trixie) or 64-bit Raspberry Pi OS host (`x86_64` or `aarch64`) with root and outbound HTTPS to the control plane ([supported platforms](/docs/deployment/daemon-setup#supported-platforms)).
- **Organization owner** to mint a key; **manager** for everything else on this page except capacity.
- On self-hosted, the control plane's **public URL** configured (**Admin → Access → Hostnames**) so the install command names an address the host can reach.

## Add a server

**Servers → + Server** (the **Add server** wizard: **Name → Install → Connect**).

<Steps>
  <Step>
    **Server name (optional)** — how the row will be labelled; the daemon's hostname is used otherwise. **Continue** mints the key. Refused when capacity is exhausted (`server_capacity_exceeded`) or, on High Availability, when every license is held (`no_license_available` — **Open billing**).
  </Step>
  <Step>
    **Install command**: `curl -fsSL https://turbopanel.sh | TOKEN=… sh`. The one signed `TOKEN` value carries the key, your control plane's URLs and its key fingerprint. A High Availability control plane that has no identity key yet gives the older form, `TURBOPANEL_LICENSE=…` with `TURBOPANEL_HOST`. **Copy install command** and run it as root on the host. It installs the daemon, enrolls with the key, and starts the service.
  </Step>
  <Step>
    **Connect** waits for the daemon's first heartbeat, then opens the server. The key disappears from **Keys** the moment it is consumed.
  </Step>
</Steps>

<Callout type="info" title="The install command carries a secret">
  The key inside the command enrolls one host; treat the command as a password until it has been used. A key you will not use is deleted under **Servers → Pending keys**.
</Callout>

**Servers → Pending keys** lists the unconsumed keys (owner-only). **Delete** asks you to type the key's name. A key bound to a live server cannot be deleted from here (`license_has_attached_server`) — delete the server instead.

## All servers

**Servers** shows every server the organization holds, in **Detail** or **Summary** layout: online / offline / initializing, hostname, class, cores and RAM, the daemon build, and whether an update is available. The Overview tiles (**Servers · Cores · RAM**) total all servers.

**Updates:** servers update on their own, on both editions. There is no per-server **Update** and no batch update here; the old routes answer `410 updates_automatic`. Updates are run and paused from **Admin → Updates** ([Administering the control plane](/docs/using/admin#updates)).

## The control panel

Open a server for seven tabs: **Overview · Control · Services · Time · Network · Firewall · Metrics**. The **Firewall** tab is described in [Firewall](/docs/using/firewall).

### Overview

- **Details** — hostname, machine id, OS, daemon build, last seen, addresses.
- **Labels** — key/value labels on the server (**Add label**, **Save**). A service can pin itself to servers by label with plain Compose: `deploy.placement.constraints: ["node.labels.tier == db"]` (`==` / `!=`).
- **License tier** (TurboPanel High Availability, organization **owner** only) — the tier this server sits on (**On**), optional **Picked** tier, **required** and **recommended** tiers, unwatched uplink ids, a **tier pick notice** when a pick could not be honored (*wanted, none free*), and **Daily notice** when the hosted entitlement email last fired. When server detail includes per-tier **free** license counts, the panel lists every purchasable tier **at or above required** (when required is not yet known, only from the entry tier upward — never every rung below what the machine will need). Each row shows how many licenses are free at that tier; **Use** opens **Confirm license tier**. **Use the smallest that fits** opens **Clear license tier pick** to drop the owner pick and return to default placement. **Buy one** deep-links to Billing with that tier preselected when nothing is free. Shortfall guidance names the recommended tier and any unwatched uplinks; an overprovisioned server also shows that a lower tier would cover the hardware. See [License tiers](/docs/deployment/tiers) and [Billing](/docs/using/billing#server-license-tier-put-apiclientv1serversidlicense-tier).
- **Machine class** — **Auto** (default), **Physical** or **Virtual**. *The pin sets what is expected, not what the daemon collects*: Physical expects host sensors; Virtual does not; Auto infers Physical once sensors are discovered and never infers Virtual.
- **Web server settings** — **Hide web server names and versions**, on unless turned off. It follows the organization's setting until you switch it here; **Use organization setting** goes back. See [Hiding web server names](#hiding-web-server-names).
- **Hardware profile** — which sensors feed CPU, drive and GPU temperature, which physical NICs are monitored, the **hosting storage path** (the mount that should hold application storage; empty auto-detects), and manual **CPU TDP** / **Tjmax** overrides. Drive temperature reporting (`drivetemp`) is opt-in. What each choice changes on the Metrics tab is in [Server metrics](/docs/metrics).

### Control

- **Server proxy** — the per-server ingress container the platform manages for hosting rows; shows whether it is provisioned and running, with **Restart**. *Not provisioned* means no hosting has been deployed to this server yet.
- **Commands** — **Change hostname** (pushed to the host by command) and **Reboot server**. Commands are queued and run when the daemon leases them — an offline server picks them up on reconnect; the app shows each command's outcome and log. A command that fails shows the one line that names the cause, not the whole block of daemon output.
- **Daemon Update** — the running and channel build and a status badge. The daemon updates automatically; there is no **Update** button. **Clear Stuck Update** (managers) resets an update the daemon never reported back.
- **SSH** — the SSH port the platform uses for this server: **Use inherited** (organization → datacenter network default) or **This server** with a port; **Save SSH port**.
- **Revoke daemon key** — the compromised-host cutoff. Revoking closes the live session and refuses the key from then on; *the host cannot enroll again until this server is deleted and a rebuilt host is enrolled fresh.* Not offered for the co-located server.
- **Delete Server** — type the server's name (its hostname when it has none) in the dialog to confirm. Refused while dependent resources remain (`server_has_blockers`). While the host is online, tear down or move the environments placed here first. If the host is gone and the server shows **Offline**, see [When the host is gone](#when-the-host-is-gone). The co-located server cannot be deleted.

### Seeing what runs on a server

Open a server and choose **Services**. The tab is read-only: it lists what is attached to this host so you can see why **Delete Server** might refuse, without leaving the control plane.

**Can this server be removed?** sits at the top — **Yes** when nothing blocks delete, **No** when something still does — with the same reasons **Delete Server** on **Control** would give. When this is the co-located **Platform Server**, the card says this is the machine running the control plane itself and cannot be removed. When the host is **Offline** and delete is still blocked by leftover records, the card also points at **Delete Server** → **Host is gone** on **Control**, which forgets those records — including apps that lived only on this server — instead of asking you to stop or move them first. A database whose only copy is here still has to be deleted first. When the card says **Yes**, delete is available on **Control**.

Every delete refusal and that card name each blocking environment as **Project / Environment**, up to fifty and then **and N more** — including environments that only hold a managed database, which block delete but do not appear in **Apps** below. Blocking managed databases are listed the same way.

Below the card, each section is a list, or one quiet line when empty. If a list is long, the tab cuts it off with **and N more**:

- **Apps** — environments whose containers run here: project, environment, container name and status, and the domains they publish. Containers and domains on each app are capped the same way.
- **Databases** — managed-database members on this host (primary or replica), their engine and status.
- **Apps bound to databases** — one row per app on this server that is bound to a managed database, with the databases it uses. The database itself may live on another server.
- **Backups** — backups of databases that have a member on this server, how many, and when the latest was taken.
- **Networks and addresses** — networks this server is in, and how many addresses are assigned here.
- **Runtimes** — language runtimes the daemon has reported, and the versions it found.

The tab uses one request and refreshes while you keep it open.

### Time

- **Time sync status** — facts from the last heartbeat: whether the NTP client is enabled and **Synced**, and the servers it uses.
- **Timezone** — the effective timezone (server → datacenter network → organization default); **Apply timezone** pushes a change to the host.
- **NTP configuration** — **NTP client enabled**, **NTP servers**, **Fallback servers**; **Apply NTP** pushes it. Empty values inherit from the datacenter network or the organization's host defaults.

### Network

Read-only view of what the daemon reports and how the organization has pinned it: **Interfaces** (with the datacenter network each address is pinned into; a pin whose address the daemon stopped reporting shows **Stale**), **Datacenter Networks** (membership pins for this host), **Managed addresses** (organization address-pool rows assigned to this host), and **Mesh** (its TurboFabric state). Changing any of it is done from [Networking](/docs/using/network).

### Metrics

Live and historical charts for the host; see [Server metrics](/docs/metrics) for what each one means and [Live metrics sessions](/docs/using/admin#server-metrics) for the session limit.

## When the host is gone

If you purged the host or lost the machine, the app still lists what ran there, so **Delete Server** is refused (`server_has_blockers`) until those records are gone. **Host is gone** is only for an **Offline** server. While the host is **Online**, forget is refused (`server_online`); tear down or move apps first. The co-located server cannot be deleted.

When the server shows **Offline**, **Delete Server** opens **Host is gone**. Apps that lived only on this server are listed first — they will be removed from TurboPanel (each app in its project; a long list ends with **and N more**). The button opens a dialog that asks you to type the server's name; confirming removes the server.

**What is forgotten** (records in TurboPanel only — the machine is not touched):

- Those apps, and the containers, networks, and addresses still recorded on this server
- Replica members on this server when the database still has its main copy on another server
- Leftover deploy and storage records that still point at this host

**What is not forgotten.** A database whose only copy was on this server must be deleted first. If this server held the database's main copy and other copies exist elsewhere, move the main copy or delete the database first. Until then, forget is refused (`server_has_blockers`) and the databases are listed by name.

Forgetting is recorded in the audit log as a server delete, with counts of what was forgotten.

<Steps>
  <Step>
    Open the server. It must show **Offline**.
  </Step>
  <Step>
    On **Control**, open **Delete Server**. Read the apps that will be removed from TurboPanel (listed first), then the other records that will be forgotten. If a database is listed as blocking, delete that database first and come back.
  </Step>
  <Step>
    Type the server's name to confirm.
  </Step>
</Steps>

## Organization settings

**Servers → Settings.**

| Panel | What it sets |
| --- | --- |
| **Default server timezone** | The organization's timezone default, and **Enforce org default on every server**. |
| **Temperature display** | °C or °F on every Metrics tab. |
| **Host defaults** | The organization-level **SSH port**, **NTP client enabled**, **NTP servers**, **Fallback NTP servers** — the top of the *organization → datacenter network → server* cascade (most specific wins). |
| **Web server settings** | **Hide web server names and versions** for every server that does not set its own. On by default. |
| **Server capacity** | **Max servers** or **Unlimited servers** (owner-only). Enrolled servers and pending keys count. |

## Hiding web server names

With **Hide web server names and versions** on, a visitor cannot learn which web server answers or which version it runs. It covers every web server TurboPanel offers: Apache, nginx, OpenLiteSpeed and the front proxy that takes the public traffic.

- The `Server`, `Via` and `X-Powered-By` headers are removed from every response, whether the site runs on Apache, nginx, OpenLiteSpeed, Caddy or in a container.
- nginx stops printing its version, and Apache stops printing a footer with its name and version on error pages and directory listings. OpenLiteSpeed already leaves its version out.
- PHP never adds `X-Powered-By`; the PHP runtime keeps `expose_php` off.

The organization's **Web server settings** (**Servers → Settings**) set the default, **on**. A server's own **Web server settings** (its Overview tab) override it. The server's own value wins, then the organization's, then on.

A change reaches a site the next time its environment is deployed; saving the setting does not touch running sites. A server whose daemon is older than this setting keeps showing names until the daemon is updated.

Some default error pages still say which program wrote them, with no version, for example nginx's plain *404 Not Found* page. A site that wants its own error pages sets them in its application or server rules.

## Behind a Router

A server can sit on a LAN address (for example `192.168.1.50`) while a router forwards ports of a public address to it. The server then hosts as if it owned that public address. Everything TurboPanel runs on the server listens on all of its addresses and the firewall rules match by port, so forwarded traffic is answered like direct traffic, and the visitor's own address is kept when the router does not rewrite it. The daemon only dials out to the control plane, so it needs nothing forwarded.

What the control plane cannot see is the router's address: the daemon reports only the LAN address, and private addresses are never offered to clients. Tell the control plane the public address once, as below.

<Steps>
  <Step>
    On the router, forward TCP **80** and **443** (sites and their certificates), **15432** and **13306** if databases on this server take connections from outside, and **8443** only if the control plane itself runs on this server. Forward each to the same port on the server's LAN address.
  </Step>
  <Step>
    Install the server as usual (see [Add a server](#add-a-server)). The install command runs on the server and connects out.
  </Step>
  <Step>
    On the server's **Network** tab, open **Addresses clients use**, edit **Public**, set **Address clients use** to **A different address** and enter the router's public IPv4 (and IPv6, if the router has one). Add **DNS name clients use** if you have one. Fill **Port, if your router forwards a different one** only when the router's outside port differs from the server's.
  </Step>
  <Step>
    Point your sites' DNS names at the router's public address. Certificate requests check that a name points at one of the server's public addresses, and the saved address counts. Database connection strings show the DNS name or address and the router's ports.
  </Step>
</Steps>

- Leave a site's address pin unset. The router's public address is not one of the server's own addresses, so it cannot be chosen as a site pin; do not add it as a managed address to pin it either, because the web server cannot listen on an address that is not on the server. A pin on the server's LAN address also works: its certificate check accepts the saved public address.
- Computers on the same LAN that use the public names need the router to send traffic for its own public address back inside (often called NAT loopback or hairpin NAT), or a local DNS server that answers those names with the LAN address. A control plane that runs on such a server needs the same for its own certificate: it checks that its name answers before ordering one.
- The firewall's outside reachability check dials only the server's managed addresses, so behind a router it may say it cannot check the server.

| --- | --- |
| Install command | `curl -fsSL https://turbopanel.sh \| TOKEN=… sh` (one signed value: key, control plane URLs, key fingerprint and, for the platform CA, its fingerprint); without an identity key, the older `TURBOPANEL_LICENSE=…` and `TURBOPANEL_HOST=<public URL>` |

## Errors

| Code | Status | Meaning |
| --- | --- | --- |
| `server_capacity_exceeded` | 409 | Enrolled servers plus pending keys reach **Max servers**. |
| `no_license_available` | 409 | High Availability: every purchased license is held or releasing. |
| `license_has_attached_server` | 409 | The key is bound to a live server; delete the server, not the key. |
| `server_has_blockers` | 409 | Leftover records still reference the server (counts in the response), or a database still has its only copy or its main copy here. While the host is online, tear those down first. When it shows **Offline**, **Delete Server** can forget leftover records — except those databases, which you must delete first. |
| `server_online` | 409 | Forget leftover records is refused while the server is still connected. |
| `The co-located control plane server cannot be deleted` / `…daemon key cannot be revoked` | 403 | The control plane's own host is not removable from its own app. |
| `updates_automatic` | 410 | The retired per-server and batch update routes. Updates are automatic; see **Admin → Updates**. |
| `Server is not enrolled` | 409 | The row has no daemon key yet — the install command has not run. |
| `Invalid hostname`, `Invalid sshPort`, `Invalid ntp`, `Invalid timezone`, `Invalid machineClass` | 400 | The value did not validate. |
| `Not found` | 404 | No such server in this organization. |
