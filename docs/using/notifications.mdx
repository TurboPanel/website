# Notifications

When something happens that a person may want to know about (a server goes offline, a daemon key is revoked, access is granted), TurboPanel can put it in your **bell** and send it to your **channels**: your email, a chat room, a webhook. You decide what reaches you. This chapter covers your notification settings, the channels you and your organization own, every event that exists today, and how delivery behaves.

<Callout type="info" title="Private Alpha: The Catalog Only Lists Real Events">
  Only events that the platform actually raises are listed. Each new event joins
  the catalog together with the code that raises it, so what the settings offer
  is always what can arrive.
</Callout>

## The Model

**Nothing is on by default.** A new member receives nothing, not even in the bell, until they choose. The fastest way to start is a **preset**. **Everything can be turned off**: there are no always-on notices.

| Term | Meaning |
| --- | --- |
| **Event** | One thing that happened, with a stable code (`server.offline`), a plain name (_A server went offline_), a **severity** (info, warning, critical) and a **category** (Servers, Security, Access, Certificates, Backups, Billing, Control Plane). It belongs to one organization, or to the control plane as a whole. |
| **Level** | How much of something you want: **All**, **Warnings and Critical**, **Critical Only** or **Off**. A level is a floor: _Warnings and Critical_ lets warning and critical events through and drops info events. |
| **Channel kind** | Where a copy goes: the **bell**, **email**, **chat channels** (your personal Slack, Discord and Telegram channels) or **webhooks** (your personal webhooks). Each kind has its own level, so the bell can show everything while email carries only critical events. |
| **Scope** | Where a setting applies: **every organization** › one **organization** › one **project** › one **environment** › one **server**. The settings screens offer these five; a setting for one **service** or one **backup target** can be made through the API. |
| **Personal channel** | A channel of yours that follows your settings. Every account has one built in, **Account Email**. |
| **Organization channel** | A channel the organization's owners and managers set up, with its own rules. It is not part of anyone's personal settings. |

Where to find your settings:

- **Organization Settings → Notifications**: your own settings for that one organization. Every member can open it.
- **Account → Notifications** (`/account/notifications`): your settings for every organization at once (the **Every Organization** panel), every setting you have made anywhere (**Notification Overrides**, each with **Remove**), and your personal channels.

### How Settings Combine

On the settings screens you set a level **per channel kind** at every scope, and a level **per category** in an organization (for every channel kind at once). Through the API a setting can also name **one event**, **one personal channel**, a **service** or a **backup target**; an unsubscribe link makes one such setting for you (one category, email only). Every setting, however it was made, is listed on **Account → Notifications** under **Notification Overrides**. For each copy of each event, TurboPanel picks **the most specific setting**, compared in this order:

1. **Scope.** A server, service or backup target beats an environment, which beats a project, which beats an organization, which beats your setting for every organization.
2. **Subject**, within one scope. A single event beats a category, which beats every event.
3. **Target**, within one scope and subject. One personal channel beats a channel kind, which beats every kind.

**Scope beats subject.** If you turn the Servers category off in an organization, but set server `db-1` to **All**, `db-1`'s server events still arrive. The same rule holds for a project: Servers off in the organization, and one project set to **All**, still delivers that project's events.

**Target beats the category's own level.** A setting for one channel kind in a category (what an unsubscribe link makes) wins over the category's level for every channel. The organization's Notifications tab lists such a setting under its category with **Remove**, and an **In effect** line under the category says what applies whenever the category picker alone would be wrong, for example _In effect: Bell: All · Email: Off (Set here)_.

Today's events name either a server or only the organization, so project, environment, service and backup target settings take effect for events that name one of those as such events are added. Until then, the organization or server setting is the one that decides.

Each level on the settings screens carries a label that says where it comes from: **Set here** when a setting at this scope decides, **Effective from Every Organization**, **Effective from Organization**, **Effective from Project** and so on when it inherits one, and **Off until you turn it on** when nothing is set anywhere. A category left at **Same as Above** follows the channel kind levels above it. Removing a setting (**Reset** beside a level, **Remove** beside a listed setting, or **Reset All** on a project, environment or server) goes back to the inherited one.

### Who Can Hear What

Settings only choose among events you are allowed to see. Each event has an audience, checked again at the moment it is sent:

| Audience | Who |
| --- | --- |
| **Members** | Every member of the organization. |
| **Owners and managers** | People who own or manage the organization, directly, through a team or through the organization. These events mirror the owner-only audit trail (deletes, key changes, grant changes). |
| **Administrators** | The control plane's administrators, for events about the control plane itself. |

Administrators hear an organization's events only when they belong to it. An administrator who wants every organization's events turns on **Hear Every Organization** on **Account → Notifications**; their settings then apply to every organization on the control plane.

## Before You Begin

- You need an account on the control plane and, for organization events, membership of the organization.
- To add or change **organization channels** you must be an owner or a manager of the organization.
- An email address other than your sign-in address must be confirmed before it receives anything. Keep the inbox at hand: the confirmation link is valid for one day.

## Turn Notifications On

<Steps>
  <Step>
    Open **Account → Notifications** (the **Every Organization** panel) to choose for every organization, or **Organization Settings → Notifications** to choose for one.
  </Step>
  <Step>
    Pick a preset:

    | Preset | Bell | Email |
    | --- | --- | --- |
    | **Everything** | All | All |
    | **Recommended** | All | Warnings and Critical |
    | **Critical Only** | Critical Only | Critical Only |
    | **Nothing** | Off | Off |

    A preset sets the bell and email at that scope. Chat channels and webhooks stay as they are; set them next if you want them.

  </Step>
  <Step>
    Adjust from there: change the level of a channel kind, set a level for a category under **Categories** (organization settings only), or use **Add Override…** to give a project, environment or server its own levels. Check the label under each level to see which setting decides.
  </Step>
</Steps>

To stop everything, choose **Nothing**, or set each kind to **Off**.

## Your Account Email

Every account has a built-in personal email channel called **Account Email**. It follows your sign-in address: change the address you sign in with and notifications follow it. It cannot be deleted (turn it off with your settings instead). Your email level applies to it and to any other personal email channel; only an unsubscribe link from an email sent to another address (or the API) sets one channel on its own.

## Add a Personal Channel

Your other personal channels follow your settings just like **Account Email**: the level for their kind (email, chat channels, webhooks) at each scope.

<Steps>
  <Step>
    On **Account → Notifications**, add a channel. Pick the **kind** (Email, Webhook, Slack, Discord or Telegram) and give it a **Name**.
  </Step>
  <Step>
    Enter the **address**:

    - **Email**: any address. Your own sign-in address works at once. Any other address is sent a confirmation link, valid for one day; the channel receives nothing until someone opens it. You can send the link again after a minute.
    - **Webhook**: an `https` URL that accepts a JSON POST. You may add a **signing secret**.
    - **Slack** or **Discord**: the incoming-webhook URL.
    - **Telegram**: your bot token, a slash, then the chat id (`123456:ABC…/987654321`).

  </Step>
  <Step>
    Save. Then set the level for that kind at the scopes you want. A new chat channel or webhook receives nothing until a level for its kind is on.
  </Step>
</Steps>

Each channel row shows **Pause** / **Resume**, **Remove**, its digest and quiet hours, and the outcome of the last delivery in the past week.

## Organization Channels

An organization channel belongs to the organization, not to a person: a shared mailbox, the team's chat room, an incident webhook. Owners and managers add them from **Organization Settings → Notifications**, the same way as a personal channel, and choose **rules** for each one: **Every event** at a floor (_All_, _Warnings and Critical_, _Critical Only_), or **Chosen events** with a floor. The rules offer the organization's events only. An organization email channel may name a member's sign-in address at once; any other address gets the one-day confirmation link.

Members who are not owners or managers see a message that they need that permission instead of the list.

## The Events

19 events, grouped by category as the settings show them. **Urgent** events never wait for quiet hours or a digest.

### Servers

| Event | Code | Severity | Who can hear it | Urgent |
| --- | --- | --- | --- | --- |
| A server went offline | `server.offline` | critical | members | yes |
| A server was deleted | `server.deleted` | info | owners and managers | no |
| A folder was left behind on a server | `folder.orphans_found` | warning | owners and managers | no |
| A new server joined | `server.enrolled` | info | owners and managers | no |
| A server is running but not connecting to this control plane | `server.pin_silent` | warning | owners and managers | no |
| A server has been running for hours without connecting to this control plane | `server.pin_missing` | critical | owners and managers | yes |

_A server went offline_ also says which high availability databases had their primary on that server and what happens next. _A folder was left behind_ means folders on a server no longer belong to a service or volume: their files stay and their names stay reserved; remove them under **Folders that need attention** in the organization settings, or put the service back.

### Security

| Event | Code | Severity | Who can hear it | Urgent |
| --- | --- | --- | --- | --- |
| A server's daemon key was revoked | `server.daemon_key_revoked` | warning | owners and managers | yes |
| A software source's signing key changed | `server.repo_key_changed` | warning | owners and managers | yes |
| A server's daemon key was replaced | `server.key_replaced` | warning | owners and managers | yes |
| A server reported a different control plane key | `panel.pin_mismatch` | critical | owners and managers | yes |
| The control plane's next key changed | `panel.identity_next_changed` | warning | administrators | yes |

### Access

| Event | Code | Severity | Who can hear it | Urgent |
| --- | --- | --- | --- | --- |
| Access was granted | `access.grant_created` | info | owners and managers | yes |
| Access was revoked | `access.grant_revoked` | warning | owners and managers | yes |
| A member left or was removed | `member.removed` | warning | owners and managers | yes |

### Certificates

| Event | Code | Severity | Who can hear it | Urgent |
| --- | --- | --- | --- | --- |
| A certificate could not be issued or renewed | `certificate.renewal_failed` | warning | members | yes |
| A control plane certificate could not be renewed | `certificate.expiring` | warning | administrators | yes |

_A certificate could not be issued or renewed_ is raised when the server's check of the live site stops seeing a valid Let's Encrypt certificate. The title says _Couldn't get a certificate_ when the domain never had one, _Certificate renewal failed_ when it did, and _Stopped waiting for DNS_ when a request waited 7 days for the domain to point at the server and was dropped. A domain that keeps failing is reported once, and again only after it recovers and fails again. The sentence puts the server's error in plain words and keeps the raw text as a detail. See [Certificates](/docs/using/certificates).

### Backups

| Event | Code | Severity | Who can hear it | Urgent |
| --- | --- | --- | --- | --- |
| Where backups are copied to changed | `backup.target_changed` | warning | owners and managers | yes |

Raised when a backup target's endpoint, bucket, region, folder, addressing or keys change, or when a different target is assigned. A rename alone is not reported, and key values are never shown.

### Billing

| Event | Code | Severity | Who can hear it | Urgent |
| --- | --- | --- | --- | --- |
| A server's license tier changed | `server.license_tier_changed` | info | owners and managers | no |

### Control Plane

| Event | Code | Severity | Who can hear it | Urgent |
| --- | --- | --- | --- | --- |
| Many servers went offline at once | `fleet.mass_disconnect` | critical | administrators | yes |

This usually points at the control plane's own network rather than at the servers.

Every critical event is urgent, whatever its row says.

## The Bell

The bell in the header shows your unread count, checked once a minute; past 99 it shows **99+**. Open it for the newest items: a coloured dot for severity, the title and the sentence, and when it happened. **Mark All Read** clears the badge; **×** dismisses an item; an item that names a server opens that server. If the server, project or backup target has since been deleted, the item stays and says so, without a link. Items from an organization you have left are hidden. **Notification Settings** at the bottom opens your settings. An empty bell says **No notifications yet**, or **Nothing is turned on** when you have chosen nothing for the organization you are looking at and nothing from it can reach you; its **Turn On Notifications** link opens that organization's Notifications tab.

Reading an item in the bell cancels its email if that email is still being held for quiet hours or a digest.

## Digest and Quiet Hours

Email, chat and webhook channels can wait instead of sending each event the moment it happens. Both settings are per channel, both are off until you turn them on, and both appear on the channel's row. Personal and organization channels alike can use them.

- **Digest.** Choose **Hourly** or **Daily**. Instead of one message per event you get one summary per window: events grouped by kind with a count, the first few of each with a link back to the web interface, and "and N more" for the rest. A summary lists at most eight kinds and five events per kind. An hourly window closes at the top of the hour; a daily window closes at 08:00. A chat channel gets a short text summary; a webhook gets one JSON body with `type: "digest"`, signed like any event and sent with `X-TurboPanel-Event: digest`.
- **Quiet hours.** Choose a **start** and **end** (24-hour, for example 22:00 to 07:00; the window may cross midnight). Events that arrive inside it are held and go out as one summary when it ends. With a digest as well, held events go out with the digest window that closes after quiet hours end.

**Urgent events never wait.** Every event marked urgent in the tables above, and every critical event, is sent at once whatever the channel says. The bell is never held either.

**Which clock.** A personal channel uses your profile time zone (set from the channel row; it is yours, not the channel's). An organization channel uses the organization's default time zone. A control plane channel, or any channel with no zone set, uses UTC. Clock changes are followed: a window of 22:00 to 07:00 still ends at 07:00 on the morning the clocks change.

**Pause and resume.** A paused channel receives nothing and keeps what it was holding; **Resume** sends the held events in the next summary. Turning a digest or quiet hours off sends whatever was held at the next maintenance pass. A summary that cannot be sent is retried, not lost.

## Notification Email

Every notification email shows the event, the facts as a list, and an **Open in TurboPanel** button when the event names something you can open. The subject reads like `[TurboPanel Critical] Server db-1 went offline`.

**Unsubscribe.** Every personal notification email ends with two links: **Unsubscribe from these emails** and **Manage all notification settings**. It also carries the one-click unsubscribe headers (RFC 8058), so a mail program's own unsubscribe button works. The link opens a page that changes nothing until you press **Unsubscribe**: a mail program that opens links on its own unsubscribes no one. It works without signing in and is valid for 60 days. Unsubscribing turns off email for **that category** in **that project** (or in that organization, when the event names no project), and for that channel only when it came to a personal address other than your Account Email. Everything else stays as it was. After the press the page names the category and offers **Open Notification Settings**. To undo an unsubscribe, open that organization's **Notifications** tab (or **Account → Notifications** for an email about the control plane itself): the setting is listed under its category as _Email: Off_, or by the channel's name, with **Remove**; the **Notification Overrides** list on **Account → Notifications** has it too. Unsubscribing from a digest email, which covers every category, sets your Email level itself to **Off** at that scope; choose another level to hear email again. Email from an organization channel has no unsubscribe link, because the organization's owners and managers set its rules; it still links to the settings.

**Filtering headers.** Each notification email carries headers a mail filter can match:

| Header | Value |
| --- | --- |
| `List-Id` | `<organization id>.notifications.turbopanel` |
| `X-TurboPanel-Organization` | The organization's id |
| `X-TurboPanel-Project` | The project's id, when the event names one |
| `X-TurboPanel-Event` | The event code, for example `server.offline` |
| `X-TurboPanel-Reason` | Why you got it: `preference` (your own settings), `organization-channel` or `instance-channel` (a control plane channel) |

**Refused addresses.** When the receiving mail server refuses an address for good, TurboPanel stops sending notification email to it. Delivery starts again once the address is confirmed again. Sign-in codes and other account email are never stopped this way.

## What Webhooks and Chat Channels Receive

| Kind | Body |
| --- | --- |
| **Webhook** | JSON: `event`, `severity`, `title`, `body`, `text` (the one-line form), `organizationId`, `target` (`{ type, id }` or null), `context` (small non-secret facts), `at`. Headers `X-TurboPanel-Event: <code>` and, when the channel has a signing secret, `X-TurboPanel-Signature: sha256=<hex>`: HMAC-SHA256 of the raw body with the secret. |
| **Slack** | `{ "text": "…" }`: the title, the sentence, then `key=value` facts in parentheses. Other chat tools that read the same field work too. |
| **Discord** | `{ "content": "…" }`, the same line. |
| **Telegram** | A message to the chat id with the same line. |

Verify a webhook signature by computing `sha256=` + hex(HMAC-SHA256(secret, raw body)) and comparing it to the header with a constant-time comparison.

Three facts about channel addresses:

- **An address is a credential.** A webhook URL's path is the secret, and so is a bot token. They are stored sealed under the control plane's data-encryption key and never shown again; the screen shows the origin, or the last few characters.
- **Addresses must be `https` with no credentials in the URL.** A self-hosted control plane may reach a receiver on its own network (a `10.x` address, a bare host name). TurboPanel High Availability cannot reach a private address, so a delivery there fails and is recorded as such.
- **Delivering never blocks the thing being reported.** A webhook that is down does not stop a deploy; it leaves a failed delivery that is retried.

## Delivery and Retries

One attempt is made at the moment of the event, with a five-second budget per channel; the retry pass leaves a fresh copy alone for two minutes so a slow attempt is never sent twice. A failure (an answer other than 2xx, a timeout, a refused address) is recorded with a short code (`http_503`, `timeout`, `network`, `address_scheme_not_https`) and retried after **1, 5, 25 and 125 minutes**; after the fifth failure the delivery is **abandoned**. Email goes through the control plane's outgoing mail queue, which has its own retries. The channel row shows the last delivery's status and how many attempts it took.

## Leaving an Organization and Deleting Things

- **Leaving an organization** (or being removed) deletes your notification settings for that organization only. You stop getting its notifications at once: anything still waiting to be sent to you is dropped, and organization email channels that name your address are removed. Your settings for other organizations are untouched.
- **Deleting a project, environment, service, server or backup target** removes only the settings that name it. Anything still waiting to be sent about it is dropped. History about it keeps reading in words; it just no longer links anywhere.

## Reference

| Item | Value |
| --- | --- |
| Default | Off for everything, in every channel kind |
| Levels | All · Warnings and Critical · Critical Only · Off |
| Channel kinds in settings | bell · email · chat channels (Slack, Discord, Telegram) · webhooks |
| Scopes | every organization › organization › project › environment › server (service and backup target through the API) |

| Unsubscribe link | one category, one project or organization; valid 60 days |
| Retry | 1 → 5 → 25 → 125 minutes, five attempts, then abandoned |

## Errors

| Code | Status | Meaning |
| --- | --- | --- |
| `address_rejected` | 422 | The URL failed the outbound check; `reason` says which rule (`scheme_not_https`, `credentials_in_url`, `malformed`). |
| `address_invalid`, `address_required` | 400 | Not an email address, not a token-slash-chat-id pair, or empty. |
| `address_not_a_member` | 422 | This path accepts only your own address, or a member's sign-in address for an organization channel. Add any other address as an email channel with a confirmation link. |
| `too_many_unverified_channels` | 429 | You, or the organization, already have the most email channels waiting for confirmation. |
| `verification_mail_budget`, `address_verification_limit` | 429 | Too many confirmation emails today, from you or to that address; `Retry-After` says when to try again. |
| `too_soon` | 429 | A confirmation link was sent in the last minute; `retryAfterSeconds` and `Retry-After` say how long to wait. |
| `not_an_email_channel` | 400 | Only an email channel can be confirmed. |
| `already_verified` | 409 | The address is already confirmed. |
| `address_unreadable` | 409 | The stored address could not be read, so no link was sent. |
| `email_unavailable` | 503 | The control plane cannot send email. |
| `email_send_failed` | 502 | The confirmation email could not be sent. |
| `primary_channel` | 409 | **Account Email** cannot be deleted. Turn it off with your settings instead. |
| `personal_channel_uses_preferences` | 422 | Rules are for organization channels; a personal channel follows your settings. |
| `label_required`, `label_invalid` | 400 | The name is missing, too long, or has control characters. |
| `signing_secret_not_applicable` | 400 | Only a webhook channel signs its deliveries. |
| `signing_secret_invalid` | 400 | 1–256 characters. |
| `rule_event_unknown` | 400 | A rule names an event that is not in the catalog (`reason` carries it). |
| `rule_severity_invalid`, `rules_invalid` | 400 | The rule list is malformed. |
| `body_invalid`, `disabled_invalid` | 400 | The request body is not an object, or the pause flag is not true or false. |
| `digest_cadence_invalid` | 400 | The digest is not `hourly`, `daily` or null. |
| `quiet_hours_invalid` | 400 | Quiet hours need a start and an end as 24-hour `HH:MM`, and they cannot be the same time. |
| `time_zone_invalid` | 400 | Not a time zone from the list the web interface offers. |
| `time_zone_user_channels_only` | 422 | A time zone is set on your own profile, from one of your personal channels. |
| `timing_push_unsupported` | 422 | Digest and quiet hours are for email, chat and webhook channels only. |
| `kind_invalid`, `scope_invalid` | 400 | Not one of the kinds above, or not `user` / `organization`. |
| A sentence naming the field | 400 | A notification setting or preset is malformed: an unknown category or event, both a category and an event, both a channel and a kind, a project without its organization, an environment without its project, more than one server, service or backup target, or an unknown preset. |
| `scope_not_in_organization` | 422 | The project, environment, server, service or backup target is not in the organization the setting names. |
| `invalid_or_expired` | 400 | The unsubscribe link is damaged or older than 60 days. Sign in and change the setting from **Manage all notification settings** instead. |
| `unavailable` | 503 | The control plane cannot read unsubscribe links right now (no encryption key). |
| `Forbidden` | 403 | Organization channels need owner or manager access; **Hear Every Organization** is for administrators. |
| `Not found` | 404 | The channel, setting or bell item is not yours, or you cannot open that organization. |
| `Encryption unavailable — no encryption key configured` | 503 | The control plane has no root secret, so a sealed address cannot be stored. |
