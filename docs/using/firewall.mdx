# Firewall

TurboPanel owns the firewall on every server that runs its daemon. The installer removes `ufw`, `firewalld` and the other tools that would compete with it, and the control plane works out which doors each server should have open from what you have deployed on it. You add your own rules on top.

<Callout type="warn" title="Preview by default">
  **Nothing is applied to a server unless an operator has named it.** Every server is
  sent a **preview** of the firewall it would get: it renders the rules, asks the kernel
  to check them, loads nothing, and reports back. Applying rules is opt-in, off
  everywhere by default, and available for one named test server at a time (see
  [Turn enforcement on for one server](#turn-enforcement-on-for-one-server)). Switching it
  on for every server waits until the safety net below has been proven on a real host.
</Callout>

## The model

```
organization
├─ policy        incoming default, who may use SSH, IPv6      (Network → Firewall)
├─ rules         your own allow / block rules, org-wide or for one server
└─ servers       each has a mode and a preview               (a server's Firewall tab)
```

| Thing                  | What it is                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Inbound only**       | The firewall decides what may reach a server. Outbound traffic is always open, and TurboPanel does not restrict it.                                                                                                                                                                                                                                                            |
| **Always allowed**     | Loopback, replies to connections the server started, ICMP and ICMPv6, the DHCP client, every port the server's SSH daemon listens on, and — on a server that also runs the control plane — the control plane's own ports. These are rendered before every rule, so a rule you add cannot close them. If the server cannot tell which SSH port it uses, port **22** stays open. |
| **Worked out for you** | What you deployed: the control plane's port on its own host, hosting sites on **80** / **443**, ports published by compose services, managed-database listeners, the [TurboFabric](/docs/using/network) port, and the replication ports of high-availability databases. A service bound only to `127.0.0.1` is not exposed, so it gets no rule.                                |
| **Your rules**         | Allow, block, or block-and-tell-the-sender, for a protocol and ports, from a chosen set of sources.                                                                                                                                                                                                                                                                            |
| **Mode**               | Per server: **Off**, **Observe** or **Managed**. New servers start on **Observe**.                                                                                                                                                                                                                                                                                             |
| **Preview**            | What the server says it would load: a rule count, a digest, the kernel's verdict and the rendered ruleset.                                                                                                                                                                                                                                                                     |

One rule that is not about the firewall at all: **TurboPanel does not touch a firewall that is outside the host**. A cloud security group or a provider firewall is still yours.

## Before you begin

- You must be an organization **owner** or **manager**. Everyone else cannot see or change a server's firewall.
- A server needs a connected daemon to receive a preview.

## Modes

| Mode        | What the control plane does                                                                                                                           | Today                                                                                                                     |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **Observe** | Sends the server a preview and applies nothing. The preview refreshes when you change a rule, the policy or the mode, and when the server reconnects. | The default and the useful one.                                                                                           |
| **Managed** | Means you want this server to **enforce** its firewall.                                                                                               | Saved. It behaves like **Observe** unless an operator has also named this server (see [Turn enforcement on for one server](#turn-enforcement-on-for-one-server)); then the rules are applied with the safety net. |
| **Off**     | Sends the server nothing and leaves its firewall alone.                                                                                               | Works as described.                                                                                                       |

## Look at a server's preview

<Steps>
  <Step>
    Open the server and choose its **Firewall** tab. The banner reads **Preview
    only: nothing is applied to this server.**
  </Step>
  <Step>
    **Preview** shows the status — **Waiting for the server**, **Previewed**,
    **Would be refused** or **Failed** — with the time, the rule count and the
    digest. **Kernel check** is the server's own verdict from asking the kernel
    to test the rules.
  </Step>
  <Step>
    Expand **Rendered ruleset (IPv4)** and **Rendered ruleset (IPv6)** to read
    exactly what would be loaded.
  </Step>
  <Step>
    **What could not be worked out** lists things TurboPanel could not turn into
    a rule instead of guessing — for example a compose port with no fixed host
    port. **The server also said** carries the server's own warnings.
  </Step>
</Steps>

To change the mode, use **Mode** on the same tab. Each choice explains itself before you confirm it.

## Set the policy

**Network → Firewall** has the organization's **Policy**:

| Setting                          | Choices                                                                                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Default for incoming traffic** | **Allow by default** or **Block by default**. **Block by default** is saved and shown in previews, but a server refuses to enforce it today, so a preview of it reads **Would be refused**. |
| **Who may use SSH**              | **Anyone** (the default), or addresses and ranges such as `203.0.113.0/24`. Saved now, but it is not sent to servers until enforcement is switched on.                                      |
| **IPv6**                         | **Same rules for IPv6**, or **Leave IPv6 alone**.                                                                                                                                           |

**Save policy** stores it and refreshes the previews.

## Add a rule

**Network → Firewall** also lists the organization's **Rules**.

<Steps>
  <Step>
    **Add rule** → a **Label** (up to 48 characters: letters, digits, spaces and
    `._:/-`). It is also the comment on the rule on the server.
  </Step>
  <Step>
    **Action**: **Allow**, **Block**, or **Block and tell the sender**.
  </Step>
  <Step>
    **Protocol** (**TCP**, **UDP** or **Any protocol**) and **Port or range** —
    `5432`, or `5432-5440`.
  </Step>
  <Step>
    **Applies to**: **The server's own services**, or **Ports published by
    containers** (checked after Docker maps them).
  </Step>
  <Step>
    **Who may connect**: **Anyone**, **My other TurboPanel servers**, **This
    datacenter**, **TurboFabric only**, or **These addresses** — then one
    address or CIDR per line.
  </Step>
  <Step>**Server**: **Every server**, or one. **Save rule**.</Step>
</Steps>

Edit, **Enabled** and **Delete** are on each row. Every change refreshes the previews of the servers it touches.

How a rule reads on a published port: Docker keeps governing everything you did not restrict. An **Allow** from named sources means only those sources reach that port; an **Allow** from **Anyone** changes nothing, because that is already the case.

## The safety net

Enforcement is built to be undone automatically if it goes wrong. This is built and tested; it is being proven on a real host before enforcement is switched on for every server.

- **A new ruleset is provisional.** When enforcement is on for a server, it loads new rules for two minutes (120 seconds). They become permanent only when you run `turbopaneld firewall confirm` on the server. The control plane never confirms for you: the outside reachability check on the server's **Firewall** tab only probes, and a server's own link to the control plane proves nothing, because outbound traffic is always open.
- **Unconfirmed rules are undone.** A timer run by root, independent of the daemon, takes TurboPanel's rules out and puts back the last confirmed ones. If those cannot be loaded, the server ends up **open**, never half-restored.
- **Confirmed rules survive a reboot.** They are loaded at boot before Docker starts. Rules that were still provisional are not.
- **Nothing is applied if the safety net cannot be armed.**

If the control plane cannot be reached and you need the firewall gone, log in to the server as root and run:

```bash
/opt/turbopanel/bin/turbopaneld firewall off
```

It removes every TurboPanel firewall chain, rule, stored ruleset and pending state. `turbopaneld firewall status` shows what is pending, and `turbopaneld firewall confirm` confirms it.

## Turn enforcement on for one server

This is an **operator** step for a test server, not a setting in the app. It takes two keys, and either one alone leaves the server on previews:

1. **The operator names the server.** Set the control plane's `TURBOPANEL_FIREWALL_APPLY_SERVERS` to the server's id (its UUID) and restart the control plane. The variable accepts a comma-separated list of at most three ids; it is meant for one. A wildcard (`*`, `all`), an entry that is not a UUID, or more than three ids makes the whole list empty. TurboPanel High Availability production ignores the variable outright, so applying is not available there.
2. **An owner or manager sets the mode.** `PUT /organizations/{id}/firewall/servers/{serverId}` with `{"mode":"managed"}`. The change is recorded in the audit trail as `server.firewall_mode.set`, and the apply is sent right away.

**Before you set the variable:**

- [ ] You have out-of-band access to the server (a provider console or rescue shell), in case SSH is cut off.
- [ ] `sshd -T` on the server shows the SSH ports you expect, and they match what the control plane derived (the preview's rendered ruleset shows them).
- [ ] `ip6tables` is installed on the server, or you understand that IPv6 is then left unfiltered.
- [ ] The server does **not** also run the control plane.
- [ ] You have read a preview in **Observe** mode and its notes.
- [ ] You have let the 120-second rollback happen once, then confirmed on the second try.
- [ ] The variable names exactly one server.

**Apply and confirm.** On the server, run `/opt/turbopanel/bin/turbopaneld firewall status` to see the pending ruleset. Then run `turbopaneld firewall confirm` to keep it, or do nothing and the root guard restores the last confirmed rules after 120 seconds. The guard is armed before any rule loads; if it cannot be armed, nothing loads. A **Block by default** policy is still refused by the server whatever is sent.

**Read the state as "sent".** The app shows `applied` or `pending` for a ruleset the server's guard may already have rolled back. This build does not learn about a confirm or a rollback on the server, so check `turbopaneld firewall status` on the server.

**Turn it off.** Set the server's mode back to **Observe** (or **Off**), or remove its id from the variable and let the next send run. The control plane then sends the server a teardown that removes TurboPanel's firewall chains, forgets the stored rulesets and stops the guard, and repeats it until the server reports the removal; only then does the server go back to previews. The teardown is never blocked by the switch. If the control plane cannot be reached, `turbopaneld firewall off` on the server does the same.

## Reference

| Field           | Values                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------- |
| Mode            | `observe` (default), `managed`, `off`                                                           |
| Action          | **Allow** (`accept`), **Block** (`drop`), **Block and tell the sender** (`reject`)              |
| Protocol        | `tcp`, `udp`, `any` — **Any protocol** takes no ports                                           |
| Ports           | One port or a range `from-to`. An **Allow** rule must name ports.                               |
| Who may connect | `any`, `servers`, `datacenter`, `fabric`, `addresses` — addresses only with **These addresses** |
| Limits          | 200 rules per organization, 256 addresses per rule                                              |

## Errors

| Code                                             | Status | Meaning                                                                                 |
| ------------------------------------------------ | ------ | --------------------------------------------------------------------------------------- |
| `firewall_rule_invalid`                          | 400    | The rule failed validation; the message names the field.                                |
| `firewall_rule_limit`                            | 409    | The organization already has the maximum number of rules.                               |
| `firewall_policy_invalid`                        | 400    | The policy failed validation; the message names the field.                              |
| `firewall_mode_invalid`                          | 400    | The mode must be `observe`, `managed` or `off`.                                         |
| `serverId must be a server of this organization` | 400    | A rule named a server that belongs to another organization.                             |
| `Not found`                                      | 404    | The rule, server or organization does not exist, or it belongs to another organization. |
